# Memory and Knowledge Graph

## Memory Types

The system maintains four memory layers (see [rag-pipeline.md](./rag-pipeline.md) for the query-path diagram):

- **Short-term**: Session history stored in `chat_messages` (SQLite), managed by `SQLiteChatMessageHistory` (`memory/_history.py`), with a 30-minute TTL cache and auto-summarization when oversized.
- **Long-term**: User memories managed by `MemoryService` (`memory/_service/` with CRUD, search, extraction, consolidation, decay, profile mixins), embedded into a `memory_vectors` ChromaDB collection.
- **Episodic**: Session summaries generated by `SessionSummaryService` (`memory/_summary_service.py`), embedded into a `session_summaries` ChromaDB collection via `SummaryVectorStore` (`memory/_summary_vectorstore.py`).
- **Knowledge Graph**: Entities and relations stored in `memory_entities` and `memory_relations` (SQLite).

## Decay Formula

Memory importance decays over time so that stale facts lose relevance. The decay score is computed in `backend/src/services/memory/_decay.py`:

```
score = importance * exp(-lambda * days_elapsed)
```

Where:

| Symbol | Constant | Value | Source |
|--------|----------|-------|--------|
| `importance` | — | 1-5 scale (initial: 3) | `_common.py` |
| `lambda` | `_DECAY_RATE_PER_DAY` | settings (default 0.01) | `_common.py` |
| `days_elapsed` | — | seconds since `last_accessed` / 86400 | `_decay.py` |

At the default rate, importance halves in ~69 days (`ln(2) / 0.01`).

### Decay application

- Decay runs in a background loop (`start_memory_decay_loop`) at a configurable interval (`MEMORY_DECAY_INTERVAL_HOURS`).
- Only runs when `MEMORY_DECAY_ENABLED=true` and the interval has elapsed since the last decay pass.
- The computed score replaces the stored `importance` value in `user_memories`. Changes smaller than 0.01 are skipped.

### Retrieval scoring

When memories are retrieved for RAG context, the ranking score combines three signals:

```
score = 0.3 * semantic_similarity + 0.4 * decay_score + 0.3 * importance
```

This balances relevance (semantic similarity) with freshness (decay score) and significance (importance).

## Knowledge Graph

Entities and relations are auto-extracted from conversations via `KnowledgeGraphService`:

- Entities are stored in `memory_entities` with optional category and embedding.
- Relations link entities via `memory_relations` with a predicate string.
- Entity embeddings are managed in `backend/src/services/knowledge_graph/_vectorstore.py`.
- Entity persistence with vectorstore sync is handled by `_storage.py` (structured logging on failures).
- The entity graph is loaded into RAG context via `load_entity_context` in the pipeline (`_steps_context.py`).
